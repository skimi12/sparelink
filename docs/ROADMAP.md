# SpareLink 開発ロードマップ

最終更新：2026-11-25（日本時間）

## 目的

廃番・長納期部品を必要とする国内事業者と、余剰部品を持つ事業者の調達を支援する。最初は同一型番・少量の制御部品を仮説に置く。生成AIを使った互換性断定や架空の在庫生成は行わない。

現在の到達目標は公開デモと、実案件を扱える基礎機能の検証である。公開デモ、実受付、売買契約、実請求、利益発生を別々の到達点として記録する。

## 優先する実装

### P0：初回公開と権限

- [x] 型番・メーカー・カテゴリの検索、明示したサンプルの詳細。
- [x] 調達依頼・在庫の構造化フォーム、入力エラーと重複送信対策。
- [x] D1永続化、所有者限定の取得・終了・アーカイブ。
- [x] 管理者審査、個人情報を含めない公開レスポンス。
- [x] メーカー別名・全半角の正規化。型番の末尾・改訂・電圧は保持。
- [x] 受付フラグ・管理者権限・サンプルとテストレコードの区分。
- [x] 型検査、21件のテスト、基本ブラウザ確認、ビルド、ソース保存、公開デプロイ。
- [ ] 実サインイン後の本番保存と実端末モバイルQA。
- [ ] GitHub新規リポジトリとCI。作成権限/認証が必要なら明記。

### P1：小規模パイロットの運用

- [ ] 管理者の私的情報を含む案件詳細と対応履歴。概要一覧・審査操作の画面は初版で実装済み。
- [ ] 出所、保管環境、動作確認日、付属品、保証条件を構造化。
- [ ] 在庫確認の有効期限と再確認。古い在庫を自動的に確定在庫として表示しない。
- [ ] 相手方への連絡先共有について、対象・項目・時刻を残す個別同意。
- [ ] 本人によるエクスポート・削除申請と対応手順。バックアップと復元確認。
- [ ] 通知文の下書き、到達確認、運営者の対応期限。送信は別途許可が必要。
- [ ] 企業確認の基準と証拠。ログイン済みを企業確認済みと同一視しない。
- [x] 複数ユーザー間の権限・情報漏えいのサービス層結合テスト。
- [ ] 本番dispatch認証と実D1を通す複数アカウントの確認。

### P2：実受付と有料化

- [ ] 運営者、連絡先、対象地域・品目、販売/紹介の当事者を確定。
- [ ] 契約・物・金銭の流れを確定し、古物関連の許可/届出を個別に確認。
- [ ] 実運用の利用規約・個人情報保護方針・品質/返品/保証条件を確定。
- [ ] 金額、税、課金タイミング、返金条件を提示し、明示的な料金同意を記録。
- [ ] 決済プロバイダーのテスト環境、署名検証、冪等性、失敗/取消処理を検証。
- [ ] 実請求は適法な運営条件と利用者の承諾が揃ってから開始する。
- [ ] 実案件10件・供給企業5社を目安に、成約率・対応時間・支払意思を測る。

## 継続開発のルール

毎回 docs/HANDOFF.md と docs/VALIDATION.md を先に読む。前回の未検証事項を潰すことを、機能追加より優先する。新しい機能には、その機能を必要とする具体的な業務上の理由を残す。外部に連絡した、在庫がある、GitHubに投稿した、課金が通った、定期実行を設定した、という事実は確認結果がある場合だけ報告する。

顧客データをソースや例示資料へコピーしない。既存の別サービスや定期タスクを無断で流用・停止しない。
