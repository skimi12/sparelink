# SpareLink — 受付・案件運用・有料化の準備

更新日：2026年11月25日（日本時間）

## 1. 初期版の運用状態

初期公開版はデモです。一般利用者による実データの書き込みを停止し、管理者に限定したD1のテスト保存を用意しています。デモの案件・在庫は実在する取引や供給可能性を示しません。

次の行為は初期版では実行しません。

- 企業や個人へのメール・メッセージ送信。
- 部品の代理購入・代理販売、注文確定、契約の締結。
- 顧客の代金の預かり、決済、実請求、返金処理。

この文書の業務手順は、実受付に移る前に準備する運用モデルです。記載されている全業務が現時点でUIに実装されているという意味ではありません。実装状況はリリース記録と照合してください。

## 2. 実データの受付前に確定する情報

| 項目 | 必要な内容 |
| --- | --- |
| 運営者 | 契約主体となる実在の氏名・事業者名、必要な表示事項。架空の法人名で代用しない |
| 問い合わせ窓口 | 運営者が管理し、実際に回答できる連絡先 |
| 対応条件 | 対応できる日時、対象製品、対象地域、受付からの流れ。未検証の応答時間を保証しない |
| 個人情報 | 収集項目、利用目的、保管先、閲覧権限、保存期間、削除・開示等の問い合わせ方法 |
| 情報共有 | 企業名・担当者情報を誰にいつ共有するか。第三者共有前の個別同意 |
| 利用条件 | 情報受付と売買契約の区別、禁止事項、掲載内容の責任、訂正・削除・苦情の経路 |
| 技術運用 | 管理者認証、一般利用者のアクセス制御、バックアップ・復旧、監査履歴、障害時の窓口 |

運営者や問い合わせ先が未設定なら、一般向けの実受付を有効にしません。存在しないメールアドレス、取得していない許可・認証、架空の利用企業や取引実績を表示して不足を埋めないでください。

個人情報保護委員会は、ウェブ入力画面等から直接本人の個人情報を取得する場合、原則として利用目的の明示が必要と説明しています。新サービスの案内や提携先への提供まで、問い合わせ対応から自明だとは扱いません。

出典：[個人情報保護委員会Q4-17](https://www.ppc.go.jp/all_faq_index/faq1-q4-17/)、[同Q9-1](https://www.ppc.go.jp/all_faq_index/faq1-q9-1/)。

## 3. 受付情報と公開範囲

### 調達依頼

最低限、メーカー、完全な型番、数量、必要日、許容状態、希望する仕様・付属品、会社名、担当者の業務用連絡先を確認します。既存の調達先で断られた理由や予算は、候補を絞るための追加項目です。

### 在庫情報

型番・数量に加え、状態、入手経路、保管状況、在庫確認日、動作確認の有無・方法・日付、保証条件を確認します。写真や試験結果を扱う場合は、閲覧権限と保管方法を整えてから受付を有効にします。

### 公開・共有

- 担当者名、メールアドレス、電話番号、会社の非公開情報は一般公開しません。
- メーカー・型番・仕様の公開と、企業名・連絡先の共有を分けて扱います。
- 相手企業への個人情報の共有は、共有する項目・相手・目的を示して同意を記録してから行います。
- 写真や書類に顧客名・シリアル番号・社内情報が写り込む場合は、共有範囲を確認します。
- GitHub、公開サンプル、テストの固定データ、ログに実顧客の個人情報を入れません。

認証情報、データベース内容、顧客情報はソースコードの公開対象に含めません。デモデータは明示し、実績の数値に数えません。

## 4. 案件の基本手順

| 段階 | 運営者が行うこと | 次の段階へ進める条件 |
| --- | --- | --- |
| 受付 | 重複、対象範囲、必要情報、連絡先の確認 | 有効な依頼として処理できる |
| 条件確認 | 型番末尾、仕様、数量、必要日、状態条件を整理 | 買い手の要求が明確 |
| 候補照合 | 在庫情報と照合し、差異・不足情報を記録 | 候補と不足条件が説明できる |
| 在庫再確認 | 供給側の在庫数量・状態・出所・価格・期限を確認 | 現時点で提供可能な条件が揃う |
| 見積・紹介準備 | 条件差、売買当事者、費用、保証、連絡先共有を整理 | 当事者の同意と必要な運用条件が整う |
| 取引後確認 | 当事者が合意した範囲で結果・対応時間・問題を記録 | 成立・不成立・中止の理由が確定 |

初期デモではテストデータで手順を確認します。外部への連絡送信は自動では行いません。将来の送信作業は明示的に依頼された範囲で行います。

### 型番照合の扱い

原文の型番を保持し、検索に使う正規化値と分けます。末尾記号、改訂番号、電圧、通信方式などを無視して同一品と扱わないでください。

「型番が一致する候補」は、互換性、真贋、動作、残寿命、使用環境への適合を保証しません。候補、仕様確認済み、在庫確認済み、検査済みは別の状態として扱い、それぞれ確認者・日付・根拠を記録します。証拠がない状態を「認証済み」と表示しません。

TAYOLのFAQでも、注文時には型番の末尾コードを含めた確認を求めています。ただし、他社の保証・返品条件をSpareLinkの条件としてコピーすることはしません。

出典：[TAYOL公式FAQ](https://tayol.net/pages/faq)。

## 5. 当事者と責任の整理案

以下は有料化前に契約として確定させるための案です。現時点で当事者が合意済みの条件ではありません。

| 項目 | 整理する責任・役割 |
| --- | --- |
| 部品の所有・販売権限 | 供給企業が説明し、必要な証拠を提示する |
| 型番・数量・状態の説明 | 供給企業の情報を確認し、運営者は勝手な保証を追加しない |
| 設備への適合性 | 買い手の技術担当者が仕様確認する。代替品の設計判断は初期対象外 |
| 売買契約・請求書 | 売り手と買い手の直接契約を想定。最終的な契約主体と文面は個別に確定 |
| 配送・保険・危険負担 | 送料負担、梱包、引渡条件、破損時の連絡先を当事者が事前合意 |
| 保証・返品 | 対象不具合、検収期間、証拠、返品先、返送費、返金時期を事前に定める |
| 調達支援料 | 支払者、金額、発生条件、請求時期、取消し・返金の条件を別に定める |
| 苦情・紛争 | 受付窓口とエスカレーション先を決め、案件の経緯を保存する |

部品代金と調達支援料を混同しないでください。部品売買が解除された場合に、支援料も返金するか、既に実施した作業の対価をどう扱うかは、有料申込み前に明示します。運営者が部品代金を預かる機能は初期案に含めません。

「一切責任を負わない」という一文で実際の業務や約束が変わるとは扱わず、運営者が何を確認し、何を保証するかを具体的に定めます。

## 6. 有料化前の個別確認

### 古物営業に関する確認

愛知県警は、買い取らなくても販売委託を受け、販売後に手数料を得る営業を、許可が必要な例に挙げています。また、警察庁の古物の説明には、未使用でも使用目的で取引された物が含まれます。未使用品・B2B・手元に在庫を持たないことだけを理由に、適用外と判断しません。

次を一枚の業務図にし、所轄警察等に具体的な運営形態を示して確認します。

1. 運営者は情報提供・紹介だけを行うのか、販売委託や価格交渉の代理を受けるのか。
2. 売買契約を結ぶ者、部品を保管・発送する者、代金を受け取る者は誰か。
3. 誰が何の対価として手数料を払うのか。売買成立との関係はどうなるか。
4. 供給企業は自社の余剰品を売るのか、仕入れた商品を反復販売するのか。
5. 公開入札・競りを設けるのか、条件が公開されない個別見積なのか。
6. 事業者・取扱品に必要な許可、届出、本人確認、記録等は何か。

古物競りあっせん業の定義は、インターネット上の取引すべてを一括で扱うものではありません。神奈川県警の説明では、相互の提示条件を知ることができるか等が競りの判断に関係します。将来、オークション形式を追加する場合は、現在の説明をそのまま流用せず、再確認します。

出典：[愛知県警](https://www.pref.aichi.jp/police/shinsei/fuei/hoan/youhinokakunin.html)、[警察庁](https://www.npa.go.jp/bureau/safetylife/kobutsu/1shiryo1.pdf)、[神奈川県警](https://www.police.pref.kanagawa.jp/tetsuzuki/eigyokankei/kobutsu/mesd0046.html)。

### 料金と契約

- 料金案15%は、現時点では採算検証用の仮説です。
- 実受付時に無料であっても、将来の料金を説明する場合は無料期間と課金条件を区別します。
- 個別の見積と明示的な承諾が揃う前に請求しません。
- 有料化時には税込・税抜、最低料金の有無、請求相手、料金発生条件、キャンセル・返金条件を確定します。
- 決済・請求の利用契約や本人確認等が必要になる場合は、運営者本人の正確な情報で手続します。本人情報を推測して登録しません。
- 公開表示、利用規約、個別契約、実際の業務に矛盾がないかを確認します。

## 7. 最初の運用実験

実受付条件を満たした後、実在の調達依頼10件・協力する供給企業5社を目安に、件数を増やす前の運用実験を行います。これは市場性の確定ではなく、手順と仮定を検証する小さな試行です。

案件ごとに以下を記録します。

- 受付日、必要日、確認した型番・数量・条件。
- 有効依頼かどうかと、除外・辞退・中止した場合の理由。
- 候補提示の有無、在庫確認日、見積提示の有無。
- 買い手・売り手双方の判断と、具体的な料金条件への反応。
- 成約・非成約の結果、部品代金と支援料の区別。
- 対応時間、現金費用、トラブルと事後対応。

月次で [BUSINESS.md](./BUSINESS.md) の期待利益式を実測値に置き換えます。問い合わせ獲得のための共通営業時間や開発費も別途把握し、案件対応30分の仮定だけで全労働を表したことにしません。

## 8. 障害・情報誤り・削除依頼

実受付開始時には、誰が対応するかを割り当て、次を実行できる状態にします。

- 誤った在庫情報を訂正し、確認が必要な案件を停止できる。
- 誤送信や意図しない公開が起きた場合、追加の共有を止め、対象情報と影響範囲を確認できる。
- 問い合わせに応じ、保存データの開示・訂正・削除等の扱いを、法令・保存上の必要性に照らして判断できる。
- データ削除と、事業上・法令上必要な記録の保存を区別できる。
- 管理者権限、バックアップ、復旧手順を点検し、障害時に一般受付を停止できる。

保存期間や窓口の実値は、運営者が対応できる方針として確定します。未設定のまま、実行できない削除期限や応答時間を公約しません。

## 9. 状態変更時の確認

| 移行 | 確認すること |
| --- | --- |
| デモから実受付へ | 運営者・窓口・利用目的・公開範囲・同意・保存運用・アクセス制御が整っている |
| 実受付から紹介へ | 条件確認、在庫の再確認、連絡先共有の同意、役割分担が整っている |
| 紹介から有料化へ | 許認可等の個別確認、料金合意、責任・保証・返金、請求運用が整っている |
| 国内紹介から新形態へ | 買取・販売代理・代金預かり・公開競り・輸出入等の追加機能に応じて再確認する |

これらは事業と運用の準備条件です。収益化できること、必要な許可が取得済みであること、法的適合性が確認済みであることを表すものではありません。
